# DoshKa

**DoshKa** — це сучасна система управління завданнями у стилі Kanban, розроблена для невеликих команд. Додаток поєднує потужність мобільного Android-клієнта з надійним Python-бекендом, забезпечуючи ефективну організацію робочих процесів у реальному часі.

Назва «DoshKa» — це гра слів, що поєднує українське «дошка» (Kanban-дошка) з легким та запам'ятовуваним звучанням.

## Огляд проекту

DoshKa створено для вирішення типових проблем управління завданнями у малих та середніх командах:

- **Візуалізація робочого процесу** — класична Kanban-дошка з колонками «Очікує», «В роботі», «На перевірці», «Готово»
- **Рольова модель** — чіткий розподіл між менеджерами (створюють, редагують, переміщують задачі) та виконавцями (бачать лише свої задачі, спілкуються в чаті)
- **Офлайн-підтримка** — працюйте без інтернету, зміни синхронізуються автоматично при відновленні з'єднання
- **WIP-ліміти** — контроль кількості задач у колонках для запобігання перевантаженню
- **Біометрична автентифікація** — швидкий вхід за відбитком пальця

## Архітектура

Проект побудований за принципом клієнт-серверної архітектури:

```
┌─────────────────────┐         ┌─────────────────────┐
│   Android Client    │  HTTP   │   FastAPI Server    │
│   (Jetpack Compose) │◄───────►│   (Python 3.11+)    │
│                     │   REST  │                     │
└─────────────────────┘         └─────────────────────┘
         │                               │
         ▼                               ▼
┌─────────────────────┐         ┌─────────────────────┐
│   Room Database     │         │   SQLite Database   │
│   (локальний кеш)   │         │   (основне сховище) │
└─────────────────────┘         └─────────────────────┘
```

### Android-клієнт

- **Clean Architecture** з розділенням на шари: data, domain, ui
- **MVVM** патерн для UI-компонентів
- **Hilt** для dependency injection
- **Retrofit** для мережевих запитів
- **Room** для локального кешування та офлайн-режиму
- **Jetpack Compose** з Material Design 3 у «бруталістичному» стилі

### Бекенд

- **FastAPI** — сучасний асинхронний веб-фреймворк
- **SQLAlchemy** (async) — ORM для роботи з базою даних
- **Pydantic** — валідація даних та серіалізація
- **JWT** — автентифікація через токени
- **SQLite** — легка база даних (можна замінити на PostgreSQL)

## Функціональні можливості

### Для менеджерів

| Функція | Опис |
|---------|------|
| Управління командою | Створення команди, запрошення учасників за токеном |
| Kanban-дошка | Створення дошки з налаштовуваними колонками |
| WIP-ліміти | Встановлення максимальної кількості задач у колонці |
| Задачі | Створення, редагування, видалення, переміщення між колонками |
| Пріоритети | Критичний, Високий, Середній, Низький — з кольоровим маркуванням |
| Дедлайни | Встановлення термінів виконання з візуальним індикатором прострочення |
| Призначення | Вибір виконавця зі списку учасників команди |
| Аналітика | Дашборд з графіками розподілу задач, навантаження команди |
| Експорт | Вивантаження задач у CSV-формат |

### Для виконавців

| Функція | Опис |
|---------|------|
| Мої задачі | Перегляд лише призначених задач |
| Деталі | Перегляд опису, пріоритету, дедлайну |
| Чат | Обмін повідомленнями з менеджером у контексті задачі |
| Вкладення | Перегляд та завантаження прикріплених файлів |
| Офлайн | Доступ до закешованих даних без інтернету |

### Загальні

- **Біометричний вхід** — автентифікація відбитком пальця
- **Автовиявлення сервера** — пошук сервера в локальній мережі через UDP broadcast
- **Push-нотифікації** — сповіщення про нові повідомлення (бейдж на іконці чату)
- **Темна/світла тема** — автоматичне перемикання за системними налаштуваннями

## Встановлення та запуск

### Попередні вимоги

- **Python 3.11+** — для серверної частини
- **Android Studio Hedgehog+** — для мобільного додатку
- **JDK 17** — для компіляції Android-проекту

---

### Серверна частина (Backend)

#### 1. Клонування репозиторію

```bash
git clone https://github.com/...
cd DoshKa/server
```

#### 2. Створення віртуального середовища

**Windows:**
```bash
python -m venv venv
venv\Scripts\activate
```

**Linux/macOS:**
```bash
python3 -m venv venv
source venv/bin/activate
```

#### 3. Встановлення залежностей

```bash
pip install -r requirements.txt
```

#### 4. Налаштування змінних середовища

Скопіюйте файл `.env.example` у `.env` та відредагуйте за потребою:

```bash
cp .env.example .env
```

Вміст `.env`:
```env
SECRET_KEY=your-super-secret-key-change-in-production
DATABASE_URL=sqlite+aiosqlite:///./doshka.db
DEBUG=true
```

#### 5. Запуск сервера

**Швидкий старт (Windows):**
```bash
start.bat
```

**Або вручну:**
```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Сервер буде доступний за адресою: `http://localhost:8000`

#### 6. Наповнення тестовими даними (опціонально)

```bash
seed.bat
```

Або:
```bash
python -m app.seeder
```

Це створить:
- Менеджера: `manager@test.com` / `password123`
- Виконавця: `executor@test.com` / `password123`
- Команду, дошку, колонки та демо-задачі

#### 7. Перевірка роботи

Відкрийте у браузері:
- **Swagger UI:** http://localhost:8000/docs
- **ReDoc:** http://localhost:8000/redoc

### Мобільний додаток (Android)

#### 1. Відкриття проекту

Відкрийте папку `DoshKa` в Android Studio.

#### 2. Синхронізація Gradle

Android Studio автоматично запропонує синхронізувати проект. Натисніть **Sync Now**.

#### 3. Налаштування підключення до сервера

Відредагуйте файл `app/src/main/java/com/example/doshka/di/NetworkModule.kt`:

```kotlin
// Для локальної розробки на емуляторі:
private const val BASE_URL = "http://10.0.2.2:8000/api/v1/"

// Для реального пристрою в тій же мережі:
// private const val BASE_URL = "http://192.168.1.100:8000/api/v1/"
```


#### 4. Запуск на емуляторі або пристрої

Натисніть **Run** (Shift+F10) або використайте команду:

```bash
./gradlew installDebug
```

#### 5. Вхід у систему

Використовуйте тестові облікові записи:

| Роль         | Email            | Пароль |
|--------------|------------------|--------|
| Менеджер     | manager@test.com | 123456 |
| Виконавець 1 | dev1@test.com    | 123456 |
| Виконавець 2 | dev2@test.com    | 123456 |

## API документація

Після запуску сервера доступна інтерактивна документація:

| URL | Опис |
|-----|------|
| `/docs` | Swagger UI — інтерактивне тестування API |
| `/redoc` | ReDoc — детальна документація |

### Основні ендпоінти

#### Автентифікація

| Метод | Шлях | Опис |
|-------|------|------|
| POST | `/api/v1/auth/register` | Реєстрація користувача |
| POST | `/api/v1/auth/login` | Вхід (отримання JWT) |
| GET | `/api/v1/auth/me` | Поточний користувач |

#### Команди

| Метод | Шлях | Опис |
|-------|------|------|
| POST | `/api/v1/teams` | Створення команди |
| GET | `/api/v1/teams/my` | Моя команда |
| POST | `/api/v1/teams/invite` | Генерація запрошення |
| POST | `/api/v1/teams/join` | Приєднання за токеном |

#### Дошки та колонки

| Метод | Шлях | Опис |
|-------|------|------|
| POST | `/api/v1/boards` | Створення дошки |
| GET | `/api/v1/boards/{id}` | Отримання дошки |
| POST | `/api/v1/boards/{id}/columns` | Додавання колонки |
| PATCH | `/api/v1/columns/{id}` | Оновлення колонки (WIP-ліміт) |

#### Задачі

| Метод | Шлях | Опис |
|-------|------|------|
| POST | `/api/v1/tasks` | Створення задачі |
| GET | `/api/v1/tasks/{id}` | Отримання задачі |
| PATCH | `/api/v1/tasks/{id}` | Оновлення задачі |
| POST | `/api/v1/tasks/{id}/move` | Переміщення в колонку |
| DELETE | `/api/v1/tasks/{id}` | Видалення задачі |

#### Повідомлення

| Метод | Шлях | Опис |
|-------|------|------|
| GET | `/api/v1/messages/task/{id}` | Повідомлення задачі |
| POST | `/api/v1/messages` | Надсилання повідомлення |
| PUT | `/api/v1/messages/{id}/read` | Позначити прочитаним |

## Ролі користувачів

### Менеджер (manager)

- Повний доступ до всіх функцій
- Створення та управління командою
- CRUD-операції з дошками, колонками, задачами
- Перегляд аналітики та дашборду
- Експорт даних

### Виконавець (executor)

- Перегляд лише **призначених йому** задач
- Перегляд деталей задачі (опис, пріоритет, дедлайн, вкладення)
- Чат з менеджером у контексті задачі
- **Заборонено:** створення, редагування, переміщення, видалення задач

## Безпека

- Паролі зберігаються у хешованому вигляді (bcrypt)
- JWT-токени з обмеженим терміном дії
- Рольова модель доступу на рівні API
- Валідація всіх вхідних даних через Pydantic
- CORS-налаштування для контролю джерел запитів
